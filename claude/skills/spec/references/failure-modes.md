# 異常系の観点

受け入れ条件に異常系を入れるときに、この一覧から変更に当たる観点を選ぶ。当たらない観点は書かない。どれも当たらなければ「異常系: 該当なし: <理由>」の1行を書く。

| 観点 | 例 | 期待する結果に書くこと |
|---|---|---|
| 空・欠け | 空の入力、0件、必須の項目がない、ファイルがない | 表示か戻り値と、何も変更されないこと |
| 境界値 | 上限ちょうど、上限+1、最小値、日付や年度の境目 | どちら側が受け付けられるか |
| 不正な形式 | 型や形式の誤り、文字コード、壊れたファイル | 拒否の表示と、何も変更・送信されないこと |
| 大きいデータ | 件数や大きさが普段の100倍 | 終わるか、どこで止めるか、メモリや時間の目安 |
| 性能の低下 | 普段の件数でも変更前より遅い、重い。ループ内の問い合わせ、再描画や再計算の増加、キャッシュが効かなくなる | 変更前と変更後を同じ条件で測った値（時間、メモリ、リクエストの数）と、許容する差 |
| 再実行 | 同じ操作を2回、途中から再実行 | 二重に作られないか、結果が同じか |
| 途中の失敗 | 書き込みの途中で落ちる、一部だけ成功する | 何が残り、何が戻るか |
| 残った状態 | 再起動後、古いキャッシュ・設定・ロックファイル | 古い状態があっても正しく動くか |
| 同時操作 | 2つの画面やプロセスから同時に変更 | どちらが残るか、壊れないか |
| 外部の失敗 | ネットワークの切断、タイムアウト、外部APIのエラー | 表示、再試行の有無、変更が残らないこと |
| 認証・権限 | ログイン切れ、権限のない利用者 | 拒否と、情報が見えないこと |

同じ原因で同じ書き方をしている箇所（修正の直し漏れ）も異常系の一種として扱い、`rg`で探した結果を前提か受け入れ条件に書く。
