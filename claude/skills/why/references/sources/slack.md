# チャット（Slack）

## 調べ方

Slack MCPを使う。最初に使えるツールを確かめる。認証に失敗したら止まり、欠落として報告する。

まず`slack_search_public`で公開チャンネルを探す。公開チャンネルで見つからず、問いに関係するプライベートチャンネルがある場合だけ`slack_search_public_and_private`を使う。プライベートチャンネルの内容を、公開される成果物にそのまま書かない。

1. **作者と期間で絞る。** PRの作者の発言を、マージ日の前後で探す。範囲が大きく絞れ、当たることが多い。
2. **PRのURLで探す。** レビューや議論の際にPRのリンクが貼られていることが多い。URLか`/pull/<number>`で検索する。
3. **エラー文で探す。** コードが特定のエラーを扱っていれば、そのエラー文で検索する。障害のスレッドが見つかることがある。
4. **スレッドを全体で読む。** 見つけた発言は`slack_read_thread`で前後を読む。

## よくある落とし穴

- **保持期間。** 古いメッセージは保持ポリシーで消えていることがある。ある日付より前が見つからなければ、その境界を記録する。
- **DM。** 多くの判断は検索できないDMで行われる。見落としは避けられない制約として記録する。
- **冗談を決定と見なす。** Slackは気軽な場である。「とりあえずやっちゃおう」は、コミットの直前にあっても判断ではない。検討のあるやりとりを探す。
- **単独の発言の文脈落ち。** スレッドなしの1発言は、文脈の中と違って読めることが多い。必ずスレッドを読む。
- **認証の失敗。** MCPが認証されていなければ止まる。結果を作らず、Slackは調べられなかったと報告する。
