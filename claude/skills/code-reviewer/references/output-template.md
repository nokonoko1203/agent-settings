# レビュー結果

指摘を最初に示し、残りは判断に必要な節だけを使う。見出しの言語は回答に合わせる。

## 指摘

各指摘に重大度、ファイルと位置、発生条件、今回の変更で起きる理由、影響、修正の方向性を含める。指摘がなければその旨を述べる。

## 影響範囲

`references/blast-radius.md`の手順を使った場合だけ書く。安全の根拠になる事実、到達した確からしさの段階と証明（または「未証明」）、リスク、問題なしと確認したもの、マージ前に実行する最も安い確認。

## 必要な補足

検証漏れ、設計上の注意、未確定の仕様、残るリスクから該当するものを示す。同じ問題を複数の節へ重ねない。指摘がないことを埋め合わせるための懸念は加えない。

## 確認範囲

変更の意図、確認した経路と証拠、判断に影響する未実施の確認を簡潔に記す。変更概要が既に伝わっている場合は重ねない。
