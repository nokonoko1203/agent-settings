# 性能の改善

すべての変更を計測に結び付ける。コードを読むだけで遅い箇所を決めつけない。

1. 先に基準の値を計測する。値は[`../references/benchmark-checklist.md`](../references/benchmark-checklist.md)で確かめる。
2. `how`で仕組みを読み、計測の結果から仮説を立てる。上限を主張するなら、先に実行して確かめる。
3. 速くする方法は、安い順に試す。早い段階の方法で目標に届いたら、そこで止める。
   1. やめる。使われていない結果を作らない。
   2. 二度やらない。
   3. 量を減らす。
   4. 後でやる。
   5. 待たせないときにやる。
   6. 並行にやる。
   7. 処理を安くする。
4. 1つ試すごとに計測し、効かなかった変更は戻す。
5. 修正前と修正後を同じ条件で計測し、`benchmark-checklist.md`で確かめた値を`evidence.md`に書く。結果がはっきりしないものは合格にしない。

原因の診断だけを頼まれた場合は、手順2で止め、計測の記録と原因のファイルと行を報告する。不確実性が大きく、方式から決める必要があると分かったら、レベルRに上げて`spike-rebuild`に切り替える。

報告: 修正前の値、修正後の値、差、計測の回数と幅、ボトルネック、記録の置き場所。
