# 重大度基準

## P0

- 即時に止めるべき
- データ破損、重大なセキュリティ事故、広範囲障害、不可逆な破壊を招く

## P1

- 高優先度で止めるべき
- 主要機能の破綻、明確な回帰、運用で回避しづらい障害につながる

## P2

- 中優先度の重要指摘
- 今すぐ全面停止ではないが、回帰や未検知障害を将来高確率で生む
- テストやCIの穴、設計不整合、重要な前提漏れがここに入ることが多い

## P3

- 低優先度
- 実害は限定的だが、将来の誤用や保守難を招く

## 補助ルール

- 迷ったら、実害の大きさと再現確率で決める
- 「気になる」ではなく、「どう壊れるか」が言えないなら重大度を付けてfindingにしない
- 単なる改善提案は`Architecture notes`か`Residual risks`へ回す
